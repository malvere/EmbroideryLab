# EmbroideryLab

## Public source and releases

Published source: https://github.com/malvere/EmbroideryLab. Windows binaries: https://github.com/malvere/EmbroideryLab/releases/latest.

The independent public checkout is `publication/EmbroideryLab/` under the workspace root. It starts with a clean history and contains source, portable build scripts, public documentation and original synthetic test fixtures. This research checkout retains private artwork-derived outputs and historical analysis; its history must not be pushed to the public repository. User samples, their derivatives, research dumps and local validation outputs are excluded from the public checkout. Release archives are generated by `tools/package-release.ps1` and include the applicable dependency/font/Rust licenses.

Independent Rust embroidery editor for flat-color artwork. Windows is tested; the core is separate from egui/eframe. This remains a development digitizer, with no production stitch-out claim.

From the workspace root run tools/build.ps1, then tools/run.ps1. Add -Release to build or run optimized binaries. Rust/cargo 1.99.1 and portable GCC-MinGW are installed for this VM. The GNU target requires gcc.exe on PATH; tools/build.ps1 also discovers the local tools/winlibs installation. macOS/Linux builds have not been verified.

## Workflow

**Загрузка изображений:** кнопка **Автооцифровка…** или **Файл → Загрузить изображение…** принимает JPEG (`.jpg` и `.jpeg`), PNG, WebP, PDF и SVG. Файл также можно перетащить в окно редактора или открыть через **Открыть…**. Для JPEG, PNG и WebP сначала открывается предпросмотр с выбором фона, размера и параметров трассировки. В PDF выберите нужную страницу кнопками **Предыдущая страница / Следующая страница** или номером страницы; загружается одна страница за раз. **Сгенерировать вышивку** переводит выбранное изображение в редактируемые объекты. Отмена загрузки и ошибки чтения сохраняют текущий проект.

PDF обрабатывается в фоне с возможностью отмены. Страница растеризуется с сохранением пропорций, до 2048 пикселей по длинной стороне, затем проходит ту же трассировку, что JPEG/PNG. Это импорт изображения страницы, а не прямое редактирование PDF-векторов. Изображение выбранной страницы встраивается в ELAB как PNG и доступно без оригинального PDF. Для PDF с паролем нужна копия без пароля. CLI `generate` и `project` импортируют первую страницу PDF.

Windows-скрипты сборки и запуска подготавливают закреплённый PDFium 8125 с проверкой SHA256. Первый запуск подготовки требует загрузки компонента; затем используется проверенная локальная копия. Для переноса приложения используйте полный ZIP или переносите `pdfium.dll` и лицензии вместе с EXE. Ручная подготовка: `tools/setup-pdfium.ps1`.

Open JPG/PNG to review the saved source, choose a physical width and palette, and click **Generate embroidery**. The GUI starts at 512 px / 8 colors and retains opaque white. **Select by colour** uses a fixed source seed and perceptual OKLab tolerance: hold the left button and drag farther to widen the range; return to narrow. Connected region, exterior background and all-similar modes are explicit. Delete applies a nondestructive exclusion mask; protection/restoration brushes and operation-level Undo/Redo retain interior details. Light-fringe removal is a local preview, not full unmatting. Advanced tracing includes exact pinned palette colors, physical area thresholds and bounded isolated-noise cleanup. See [Russian usage](../docs/autodigitize-usage.md) and [design/invariants](../docs/autodigitize-design.md).

For a gray antialiased fringe, exclude the exterior white first, then use **Light fringe → Preview light fringe removal** and inspect the mask before applying it. The local mixture check retains the dark core and solid gray details; protect an intentional thin gray edge before cleanup. Physical smoothing limits and preserved decisions during source re-digitization are described in [algorithm completion](../docs/algorithm-completion.md).

Tracing, conservative stitch classification and generation run in revision-checked cancellable workers. A result commits in one Undo operation; error or cancellation retains the document and last valid plan. Generate uses edited objects without retracing. **Redigitize saved source** is separate and transfers manual decisions only when source-region identity is proven; changed topology reports a conflict. The technical source/mask/regions/stitches preview shows actual machine coordinates. Stale results cannot be exported.

Select objects at left, drag polygon nodes or Bezier handles, change stitch settings and choose Generate stitches. Earlier/Later controls sewing order and overlaps. Draw contour plus clicks creates a ring; Enter completes, Escape cancels. Rectangle and Bezier add editable objects. Delete removes the selected polygon node, Satin node/direction rung, or selected centerline branch; minimum valid geometry is retained. Wheel zooms, middle drag pans, Fit design resets the viewport. Ctrl+O/S/E/Z open/save/export-DST/undo; Ctrl+Y and Ctrl+Shift+Z redo. A drag or continuous field edit is one history operation. History retains up to 30 operations; a new edit after Undo clears Redo.

**3D-просмотр стежков:** переключатель **Вектор / Стежки / 3D** над холстом меняет центральный вид, сохраняя список объектов, параметры и симуляцию. В 3D стежки показаны объёмными изогнутыми нитями с освещением и перекрытиями над плоскостью ткани. Левая кнопка мыши вращает и наклоняет вид; средняя или правая кнопка сдвигает его; колесо меняет масштаб. **Показать целиком** или двойной щелчок сбрасывает камеру. **Диаметр нити (мм)** меняет только изображение: геометрия проекта и экспорт остаются прежними. Для 3D нужен OpenGL 3.3 или новее. Это геометрический предпросмотр; физическое качество вышивки проверяется на пробном отшиве.

Ползунок симуляции ограничивает 3D текущей командой. Предрассчитанная тень полного рисунка появляется, когда показаны все стежки; промежуточные кадры показывают уже выполненные нити. После изменения геометрии или параметров нажмите **Сгенерировать вышивку**, чтобы обновить вид. Незавершённый контур, Satin или другой предпросмотр нужно завершить либо отменить перед переходом в 3D; переключатель сохраняет незавершённую работу.

**Размер вышивки** отображается рядом с количеством стежков как **ширина × высота в мм** и доступен для проектов и открытых DST/DSB. Он охватывает концы всех вышиваемых сегментов и относится ко всему рисунку независимо от положения симуляции. Переходы и смещения при смене цвета задают начало следующего стежка и учитываются только там, где затем проходит нить. Размер исходного изображения и пялец в этот показатель не входят. Для устаревшего или пустого набора стежков показано **Размер: —**; успешная генерация обновляет измерение.

**Правая кнопка мыши:** нажмите на объект на 2D-холсте или его имя в списке. В меню **Параметры** доступны название, цвет нити, тип и параметры стежков, а также координаты выбранного узла. **Редактирование** открывает правку узлов, разворот направления, порядок вышивки, удаление и существующие инструменты геометрии. Изменения поддерживают отмену и повтор. На холсте ПКМ выбирает видимый объект под указателем; щелчок по пустому месту открывает меню текущего объекта. Незавершённый контур сохраняется при открытии меню. В режиме просмотра DST/DSB редактирование недоступно.

**Выделение областей рамкой:** в режиме **2D → Правка узлов** зажмите правую кнопку мыши и протяните рамку. После отпускания выделяются все видимые области и линии, пересекающие рамку; они подсвечиваются на рисунке и в списке объектов. **Ctrl** или **Shift** добавляет области к выделению, пустая рамка без модификаторов снимает выделение, **Escape** отменяет текущую рамку. Короткий правый щелчок открывает прежнее меню. Параметры относятся к активному объекту; выбранную группу можно использовать для существующего объединения областей.

**Выбор слоёв в списке:** обычный щелчок выбирает один слой, **Shift + щелчок** — диапазон от исходного слоя, **Ctrl + щелчок** добавляет слой или снимает его выделение, **Ctrl + Shift + щелчок** добавляет диапазон. **Ctrl+A** выбирает все слои, включая скрытые; в поле ввода это сочетание выделяет текст. Выбор слоёв не меняет их видимость и параметры.

**Satin editor / Редактор Satin** adds manual drawing to paired-rail objects. Choose **Draw satin / Нарисовать Satin**, click the first side and press Enter, then draw the second side in the same direction and press Enter again. Escape cancels the unfinished draft. Blue and coral nodes identify the two sides. Drag nodes or edit coordinates, **Insert node after / Добавить узел после выбранного** and **Delete node / Удалить узел**, and enable **Smooth node / Гладкий узел** to shape curved sides with handles. Spacing means same-rail puncture spacing; direction follows the sides rather than the global fill-angle setting.

**Add direction rung / Добавить направляющую стежков** links one side to the other. Direction rungs must progress along both sides without crossing. Select a rung to change its normalized positions or delete it. **Split at rung / middle / Разделить по направляющей / посередине** splits at the selected rung or halfway along the column; use separate columns for tight corners. Reverse changes both side directions. Crossed, collapsed or ambiguous geometry reports an error and cannot produce a current export. A plain contour set to Satin still uses the earlier scanline zigzag baseline.

For borders, choose **Draw outline / Нарисовать обводку**, place the center path, set **Outline width / Ширина обводки**, and choose open or closed. **Preview outline / Предпросмотр обводки** builds the two offset sides; **Apply outline / Применить обводку** creates an editable Satin object. An existing object's first contour or Running path can also supply the outline path. Closed outlines preserve their interior opening and expose a start-position control; narrow offsets, self-intersections and paths that collapse or separate need manual correction or splitting. Centerwalk, edgewalk and zigzag underlay have separate controls; inset, spacing and stitch length apply to the added underlay passes.

For an area's axes, select the object and expand **Centerlines** at the top of Stitch settings. Choose pixel size in mm (0.20 default; smaller retains finer details) and **Create running copy**. Extraction runs in a background worker with Cancel. Success inserts a Running object after the source and hides the original area; Undo restores the complete prior project. Drag circular path nodes or edit a selected node's coordinates, reverse direction, set maximum stitch length and ties, then Generate stitches and export. Separate graph branches begin with Jump; open endpoints are never implicitly joined. Explicit loops retain their closure while editing. Hidden source geometry remains in the saved project.

This is independent Guo–Hall raster skeletonization, corresponding to the useful skeleton-preprocessing capability found in the graphics SDK. The Rust code neither loads the DLLs nor incorporates their implementations. It preserves raster topology, but rasterization can lose subpixel details; curves may retain corner spurs and small stitches. Exact straight runs are compressed without changing geometry. Isolated pixels are reported and omitted from stitching.

In **Branch cleanup / Очистка осевых линий**, choose a whole branch to delete it, inspect local width, or preview smoothing with a maximum error in mm. Apply only the reviewed result. Shared junctions and explicit loops retain their topology; edits that leave the source region, collapse segments or introduce crossings are rejected. Local width is twice the nearest-boundary distance, an estimate rather than a Satin cross-section. It uses the graph's immutable source-region snapshot; later edits to the original object do not silently update that width. **Preview branch as satin / Предпросмотр ветви как Satin** attempts a semi-automatic pair of sides; **Create satin copy / Создать копию Satin** commits an editable copy. Conversion currently requires an open branch with degree=1 at both ends. Junctions and closed branches require manual outline/Satin editing or splitting; sections wider than 12 mm, holes and ambiguous side correspondence need manual correction. This is not unattended automatic lettering or a fabric-quality guarantee.

**Preview mask / Предпросмотр маски** in raster import shows the current traced regions before document replacement. Click a region to include/exclude it. Rebuild the preview after changing trace settings. Manual region choices are matched by geometry/color identity; changed identities require an explicit **Reset mask / Сбросить маску** rather than silently discarding choices. **Regions and objects / Области и объекты** offers a straight two-point cutting line and merging of Ctrl-selected same-thread-color regions. Cuts preserve filled occupancy and holes; union removes overlaps and retains holes that other selected geometry does not fill. The earliest merged object supplies its settings and sewing position.

Save project writes readable JSON ELAB. Schema v5 stores the full saved source, source-coordinate cleanup/protection masks, physical scale, palette/recipe, proven source identities, diagnostics and machine limits. Versions v1–v4 remain readable. New source embedding is lossless up to 12 MB and the project limit is 32 MB; an oversized source is explicitly rejected rather than silently downsampled away from its cleanup mask. User geometry, thread colors, settings and added/deleted objects survive regeneration. Old editors reject v5 rather than discarding its recipe. History and unfinished drafts remain session state.

Save replaces files through a synced temporary file beside the destination. Dirty editable projects write a recovery copy every 30 seconds without replacing the last saved document. Named projects use a separate `.filename.recovery.elab` beside the project; unsaved work uses `%LOCALAPPDATA%/EmbroideryLab/Recovery/unsaved.elab`. When offered a recovery copy, choose **Restore recovery / Восстановить копию** or **Discard recovery / Удалить копию**. Undo/Redo history and unfinished drafts are session state and are not stored in ELAB.

**Quality checks / Проверка качества** separates top fill, underlay, sewn travel and locks, and reports empty/sub-grid objects, invalid Satin, protected-boundary crossings, sampled top-thread coverage, repeated top segments, long stitches/jumps, trim intentions and configured machine limits. Puncture density and exact clipped segment-length density are separate diagnostics; the latter has its own 2D heat map. Warnings focus the corresponding object or source position. Coverage uses an explicit assumed thread width, not the visual 3D diameter. These bounded geometric checks do not certify fabric performance.

Simulation follows actual command order. DST opens in stitch-only mode: it cannot reconstruct vectors or exact thread colors. DSB also retains its distinct raw Trim/Stop/Needle commands for DSB re-export. Save project and vector-generation actions are disabled for machine-only views. DSB-preview-to-DST conversion is blocked to prevent losing machine controls.

Export DST validates the result by decoding it. Export DSB is experimental: generated color changes become manual Stop commands, with physical thread/needle mapping left to the controller/operator. Existing DSB commands survive semantic re-export, but header metadata, padding and unused payload bytes are rewritten. Unknown command variants are errors. Machine and fabric acceptance remain unverified.

## CLI

Binary: embroidery-engine/target/debug/embroidery-cli.exe. Run from the repository root:

```text
embroidery-cli generate artwork.svg outputs/artwork.dst 100
embroidery-cli generate artwork.elab outputs/artwork.dsb
embroidery-cli generate-with-options artwork.jpg outputs/trace.dst 100 options.json
embroidery-cli project artwork.png outputs/artwork.elab 100
embroidery-cli satin-demo outputs/satin.dst
embroidery-cli centerlines artwork.elab outputs/axes.dst 1 0.20
embroidery-cli satin-outline artwork.elab outputs/border.dst 1 2.0 closed
embroidery-cli satin-from-branch outputs/axes.elab outputs/letter.dst 2 1
embroidery-cli quality outputs/letter.elab outputs/letter.quality.json
embroidery-cli inspect samples/1.dst
embroidery-cli inspect C:/EMBIRD32/Files/Cat.DSB
embroidery-cli roundtrip samples/1.dst outputs/roundtrip.dst
embroidery-cli dsb-roundtrip input.dsb outputs/roundtrip.dsb
embroidery-cli dsb-records input.dsb outputs/records.json
embroidery-cli dsb-from-dst input.dst outputs/manual-stops.dsb
embroidery-cli render input.dsb outputs/preview.svg
```

Generate also saves ELAB, stitch JSON and SVG. generate-with-options adds an import.json sidecar. Example options (the colors below are illustrative, not inferred fabric):

```json
{"max_dimension":512,"palette_size":8,"background":{"ConnectedColors":{"rgb":[[225,166,43],[255,255,255]],"tolerance":35.0}},"min_region_pixels":6,"simplify_tolerance_mm":0.1,"smoothing_iterations":0}
```

The API also accepts ConnectedBorder for exterior-only perimeter estimation, and legacy Color/Colors/Border for global masks. All connected masks use four-neighbor connectivity on the tracing-resolution image. The NearWhite API default remains compatible with older versions.

`centerlines` takes an ELAB input, a DST/DSB output, a 1-based object number and optional pixel size (mm). It saves the whole resulting project, retaining other objects' visibility, plus a `.centerlines.json` report with paths, isolated points and pixel counts. For an isolated result, start with a one-object project. The library APIs are `thinning::skeletonize`, `centerline::extract` and transactional `centerline_workflow::running_copy`. Masks are 0/1 with 8-connected foreground and 4-connected background; extraction limits include 2048 pixels per axis, 4M pixels, 100k path nodes and explicit work budgets. Oversized areas require a larger pixel size.

`satin-outline INPUT.elab OUTPUT.dst OBJECT_NUMBER WIDTH_MM [open|closed]` builds an editable Satin border from the selected object's first contour or Running path. Output may also be DSB. The width is in mm; object numbers are 1-based. `satin-from-branch INPUT.elab OUTPUT.dst OBJECT_NUMBER BRANCH_NUMBER` converts a selected editable centerline branch after the same geometric checks used by the GUI. Branch numbers are also 1-based. Both commands save the resulting ELAB and machine preview outputs; inspect the rails before sewing.

`quality INPUT.elab OUTPUT.json` analyzes generated project stitches; `INPUT.dst` and `INPUT.dsb` analyze decoded machine previews. The JSON report records the advisory short-stitch, long-jump and density findings with command locations. These checks do not certify a machine sew-out.

API limits: 16–2048 tracing pixels, 2–32 colors, explicit complexity limits; GUI offers a smaller practical preset range. Small images are not upscaled. SVG supports opaque solid fills, outlined strokes (including dashes and caps/joins), paint order, transforms, nonzero/evenodd geometry and local use references. Text must be converted to paths; raster images, gradients, masks, actual clipping and filters remain explicit unsupported inputs. See [svg-import.md](../docs/svg-import.md). Tatami and sparse underlay fill continuous blocks around holes and separate islands rather than alternating between them on every row. Safe direct connectors remain bounded; long curved hidden travel remains future work. Paired-side Satin adds edgewalk/zigzag underlay; Tatami punctures use a four-row physical stagger consistent across blocks. Compensation and automatic direction are geometric heuristics, not fabric simulation.

Pull compensation rejects newly touching or overlapping regions across an originally open gap, within one object or between visible fill objects. Reduce compensation or widen the gap before generating again; spans are never silently clipped to make the check pass. Bounding boxes filter candidates before bounded exact geometric checks, including islands inside holes and Satin rail-normal expansion. Pre-existing shared contacts and intentional layer overlaps retain the existing policy: each object applies its configured compensation, so inspect any resulting overlap. The default remains zero compensation.

Sparse Tatami underlay has its own inset, spacing, stitch length and absolute direction. By default its direction follows the top angle + 90°; clear that option to set an angle from −180° to 180°. An explicit direction is saved in ELAB v5. Older projects keep the previous direction and machine path, while Satin underlay continues to follow its rails.

## Verification and provenance

The 0.5 full run passed **162 Rust tests, 0 failed, 1 ignored** (the installed external DSB corpus test). After the final GUI layout/copy fix, its 28 GUI/state tests were repeated successfully; GUI/CLI build, strict Clippy for all targets with capture, and formatting passed. These repeated tests are a subset of the full count. New coverage includes cubic rail edits/splits, direction rungs, closed seams and holes, underlay, graph cleanup/smoothing, region split/union, history, source persistence and atomic recovery.

`tools/quality_v05.py` passed **8 cases × DST/DSB** and **4 rejection checks** on the final CLI. Pinned pyembroidery 1.5.1 independently matched all **2007 needle coordinates per format** to quantized JSON. Reopening ELAB produced identical machine bytes; existing outputs survived invalid-input rejection. There were no samples beyond the 0.13 mm diagnostic boundary band among **57,213 probes per format**; the actual maximum outside distance was 0.062256 mm. These are bounded samples, not strict containment or fabric validation. The spur-cleanup fixture was prepared manually, while Rust API tests cover the deletion operation. The real-letter case checks Running regression rather than automatic Satin success. See [validation_v0_5.md](../reports/validation_v0_5.md), [gallery](../outputs/quality_v05/index.html) and [summary with hashes](../outputs/quality_v05/summary.json).

Final framebuffer captures were reviewed at 1360×900 and 1024×680 in Russian and 1024×680 in English. A long direction-rung list found in the first pass was changed to a bounded scroll with fields for the selected rung. Accessibility actions covered beginning/cancelling Satin, applying a closed outline and Undo/Redo before the final fixes. Helper screenshots were white and the Save-dialog action hit a helper coordinate error, so a new manual save/export/reopen flow is not claimed. Captures do not establish every control below the fold, full keyboard editing, screen-reader or high-DPI acceptance.

Historical 0.4 evidence remains in reports/validation_v0_4.md and reports/quality_centerlines_v04.md: 106 passing tests, all 65,536 4×4 masks, 1,024 frontier/full-scan comparisons and seven limited centerline export cases. Earlier 0.3 reports retain the nine-case routing comparison, 22,205 coverage probes and prior OS-dialog flow. Explicit Running bends remain preserved before quantization; a path collapsing entirely on the 0.1 mm grid is rejected. No physical sew-out or whole-GUI certification is claimed.

On the one real JPG in the historical 0.3 comparison with identical settings, DST jumps fell 10735→10224 and jump distance 33883.47→32211.05mm. IoU with the existing Embird reference changed only 0.440851→0.441985. Version 0.5 adds manual borders and semi-automatic branch-to-Satin correction; arbitrary lettering, technological overlaps and fabric deformation are not automatically inferred. Connected masks are a separate user choice, not universally higher quality.

For render captures build with cargo build --features capture --bins, then run tools/capture.ps1 (optional -Size 1024x680). This uses the public eframe screenshot API and exits after capture; it is not a pointer or file-dialog test. AccessKit is enabled, but full keyboard canvas editing remains future work.

New source is independent of Embird pseudocode. Embird binaries/manuals and user samples retain their ownership and are excluded from Git. Format evidence: pyembroidery DstReader/DstWriter and DsbReader; pinned local DsbReader hash and contradictory older DSB interpretations are documented in reports/dsb_format.md. Machine manual findings are in reports/machine_profile.md. No physical machine is controlled.

Legacy ELAB v3 Running paths remain independent. Individual paths can be deleted without guessing shared junctions; the final path is removed with its object. Width, constrained smoothing and branch-to-Satin conversion require an extracted source graph.


## Current autodigitizing validation

Current-session evidence, exact baseline/candidate settings and limitations are in [autodigitize-validation.md](../docs/autodigitize-validation.md). Historical totals below describe their own versions. The new `autodigitize INPUT.png OUTPUT.dst [WIDTH_MM] [OPTIONS.json]` CLI runs the same cleanup, editable classification and stitch engine as the GUI and saves ELAB, normalized plan, commands and thread sidecars. `quality` adds top-only coverage and segment-density data. DST trim intent is encoded by an explicit profile (three stationary jumps or deliberately retaining uncut thread); it is not a universal machine trim opcode. DSB remains experimental.

Raster import supports JPEG, PNG and WebP and detects actual content for mislabeled filenames. WebP artwork is embedded losslessly as PNG, preserving existing ELAB source compatibility. See [image-import-compatibility.md](../docs/image-import-compatibility.md).
