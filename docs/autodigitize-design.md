# Автооцифровка: решения и инварианты

**Срез базового этапа.** Незакрытые пункты этого среза (вырезание скрытых слоёв,
оценка/повторы travel, ограничение сглаживания, серая кайма и повторная
классификация) доделаны после повторной сверки. Актуальное описание:
[завершение алгоритмов](algorithm-completion.md). Исторические ограничения
ниже не являются списком оставшихся работ текущей сборки.

Дата проверки реализации: 6 ноября 2026. Результаты запусков и измерения приведены отдельно в [autodigitize-validation.md](autodigitize-validation.md). Поддерживаемая цель — флаги, эмблемы, плоские логотипы и контурные рисунки. Ограничение палитры сложного изображения не является фотостичем; автоматическое распознавание произвольного фото и мелких букв не заявлено.

## Один тракт в существующем приложении

```text
сохранённый RGBA + маски в исходных пикселях
  → premultiplied-alpha resize → OKLab-палитра → карта меток
  → 4-связные компоненты / кольца / общие границы
  → редактируемые Object + необязательная классификация
  → геометрия проходов → MachinePlan → нормализация 0,1 мм
  → общий 2D/3D-просмотр, диагностика, DST/DSB
```

Основной код остаётся на Rust, `egui`/`eframe`, `image`, `geo`, `cavalier_contours`. Второго генератора рядом с `engine.rs` нет. Python используется только для независимых проверок и корпуса.

| Узел | Ответственность |
|---|---|
| `color_selection.rs` | Фиксированный опорный цвет, OKLab, связность, маски, локальная кайма, alpha-resize |
| `raster_options.rs`, `import.rs` | Палитра, метки, компоненты, трассировка, отчёт об исключённых деталях |
| `autodigitize.rs`, существующие `centerline` / `axis_edit` | Физические пороги классификации и конструктивные Satin rails |
| `fill_geometry.rs`, `engine.rs` | Компоненты even-odd, компенсация, подложка, безопасные переходы, проходы |
| `commands.rs`, `dst.rs`, `dsb.rs` | Единая позиционная семантика, квантование, машинные записи |
| `cleanup_ui.rs`, `digitize_job.rs` | Жест, предпросмотр, фоновые задания, ревизии, транзакционное применение |
| `persistence.rs`, `model.rs` | ELAB v5, исходник, рецепт, ручные решения и профиль ограничений |

## Координаты, геометрия и команды

Редактирование, шаги, длины, inset и компенсация измеряются в мм, площадь — в мм². Уменьшенное изображение сохраняет физическое соотношение сторон даже при округлении размеров thumbnail: масштабы X и Y вычисляются отдельно. Плотность не зависит от zoom или DPI.

Исходные кольца объекта не изменяются при компенсации. Для каждого компонента отдельно строится направленное расширение наружной оболочки вдоль направления заполнения; исходные отверстия вычитаются без расширения. `pull_comp_mm` означает **мм на каждую сторону**. Допустимая область швейных переходов соответствует этой технологической геометрии. Независимые островки не объединяются ради уменьшения Jump. Проверяется весь отрезок перехода относительно границ.

Компенсация различает наружную оболочку компоненты и защищённое отверстие. Новое касание или перекрытие исходно разделённых заполненных компонент отклоняется с указанием двух компонент и предложением уменьшить компенсацию или расширить зазор. Проверка действует внутри объекта и между видимыми Tatami/Satin, включая одностороннюю компенсацию и островки внутри отверстий; для Satin учитывается поперечное направление rails. Bounding boxes отбирают кандидатов, затем проверяется сама заполненная геометрия. Бюджеты — 2 млн проверяемых пар и 50 млн оценочных пар узлов для точных проверок; превышение вызывает ошибку, а не пропуск проверки. При нулевой компенсации всех объектов этот этап пропускается.

У исходно соприкасающихся или перекрывающихся объектов сохраняется существующая политика: каждый применяет свою компенсацию, поэтому общая граница соседних цветов может дать технологическое перекрытие. Автоматическое вычитание скрытых слоёв и согласование управляемого overlap по общей границе не реализованы; стартовое значение компенсации — 0 мм. Проверка нового контакта выполняется до квантования. Остаточный зазор меньше шага машинной сетки 0,1 мм нельзя считать гарантированно воспроизводимым; допуск проверки сегментов после квантования не является доказательством сохранения такой щели.

Подложка Tatami использует отдельную inset-геометрию, собственные `underlay_spacing_mm`, `underlay_length_mm` и необязательный абсолютный `underlay_angle_deg` в диапазоне −180…180°. При `None` сохраняется угол верха +90°: поле не записывается в JSON, старые fingerprints и траектории не меняются. Явный угол сохраняется в ELAB v5 и одинаково используется для маршрутизации, оценки работы и выполнения прохода; геометрия и параметры верхнего слоя не подменяются. Если inset уничтожает область, результат содержит причину пропуска. Satin сохраняет отдельные centerwalk, edgewalk и zigzag-проходы вдоль своих rails и не использует угол Tatami. `spacing_mm` для paired Satin — продольное расстояние между проколами **на одной стороне**; последовательные диагонали продвигаются примерно на половину этого шага. Это предотвращает ошибку ×2 при сравнении настроек.

В `MachinePlan` координаты команд и `object_id` сопровождаются параллельными `CommandMeta { role, pass_id }`. Роли: верх (`TopFill`), подложка (`Underlay`), швейный переход (`Travel`), закрепка (`Lock`), управление (`Control`). Метаданные имеют ту же длину, что список команд. `Trim` — отдельное намерение обрезки; Jump сам по себе не означает Trim. Закрепки относятся к началу/концу нити, а не к каждой строке.

Управляющие команды неподвижны. Старые перемещённые ColorChange/End нормализуются в явный Jump плюс неподвижную команду. Квантование выполняется на сетку 0,1 мм; евклидова длина швейного сегмента ограничивается отдельно от допустимых ±121 единиц по каждой оси DST. Случайные дубликаты убираются с сохранением намеренных закрепок. Проверка границ после квантования использует полудиагональ ячейки около 0,071 мм; это допуск координат, не визуальная толщина нити.

Профиль машинных ограничений отделён от настроек материала. По умолчанию не предполагаются размеры пялец или конкретная машина. Экспериментальный порог намерения обрезки — Jump 10 мм; способ DST задаётся профилем. Последовательность трёх неподвижных Jump распространена, но не является универсальным opcode обрезки. Альтернативный режим сохраняет необрезанную нить. DSB сохраняет экспериментальный статус.

## Очистка, палитра и топология

Жест фиксирует source-seed, исходный цвет, экранную точку, допуск и исходное выделение при mouse-down. Расстояния до опорного цвета кэшируются. Используется `100 × sqrt(ΔL²+Δa²+Δb²)` в OKLab после корректной линеаризации sRGB; это не CIE DeltaE. Шкала интерфейса 0–100. Текущий допуск: `clamp(T0 + 0.12 × max(distance_points − 3, 0), 0, 100)`. Логические egui points не зависят от zoom/HiDPI; ползунок допуска позволяет уйти ниже T0.

Три режима явно различаются: компонент от seed, компоненты от края и все подходящие пиксели. Связность — четыре ортогональных соседа. Цветовой диапазон фиксирован относительно seed; «дрейф» через цепочку оттенков отсутствует. Каждое движение заново совмещает кандидатов с замороженной базой через Replace/Add/Subtract, поэтому возврат курсора восстанавливает более узкое выделение. Escape отменяет жест; release вне изображения завершает его. История относится к операциям применения маски и мазкам, а не кадрам.

Исходный RGBA не перезаписывается. `CleanupMask` хранит исключение и защиту как проверяемые row-major RLE-пары `[начало, длина]` в полном разрешении исходника. Защита имеет приоритет. Рабочий preview ограничен 512 px; окончательная маска уточняется worker-ом в исходном разрешении с видимым состоянием ожидания и отменой старого вычисления. Прозрачный RGB и исключённый фон не участвуют в статистике палитры. Ресайз выполняется с premultiplied alpha, чтобы скрытый RGB не создавал кайму.

Палитра строится детерминированной взвешенной кластеризацией в OKLab без dithering. `pinned_colors` сохраняет выбранные RGB нитей точно: эти центры не сдвигаются при кластеризации, остальные слоты обучаются по изображению. Если все слоты закреплены, получается заданная пользователем фиксированная палитра. Близкие оттенки можно объединять ограничением числа цветов и закреплёнными центрами. Компоненты одного цвета остаются разными объектами. Физическая минимальная площадь задаётся отдельно от совместимого старого `min_region_pixels`; каждый пропуск имеет площадь, позицию и причину. Необязательный `denoise_passes` (0–2, по умолчанию 0) заменяет только изолированную непрозрачную метку, если все четыре соседа имеют одинаковую другую непрозрачную метку. Прозрачные отверстия и защищённые пиксели не заполняются; число и площадь замен сообщаются явно.

Число пропущенных регионов, пикселей и суммарная площадь учитываются полностью, но подробные местоположения ограничены первыми 512 в детерминированном порядке. Если их больше, `RasterTraceReport.omitted_region_details_complete` равен false, а ELAB содержит явную сводку с общими числами и количеством объединённых мест. Лимит диагностики не меняет сегментацию, геометрию или маски и не ослабляет проверку размера проекта; он предотвращает отказ импорта из-за десятков тысяч отдельных сообщений о мелком шуме.

Общая карта меток служит единым графом границ. Для соседствующих цветов сохраняются одинаковые grid-рёбра с удалением только коллинеарных точек; независимые RDP и corner-cutting на общей границе отключены. Это сохраняет T-стыки и не создаёт щелей/двойных исходных заливок. При диагональном касании пустот замкнутый обход может повторно посетить вершину: такой обход разбивается на простые циклы с сохранением всех исходных направленных рёбер и заполнения по чётности. Ни сдвиг вершины, ни hull, ни удаление петли не используются. Цена общей сетки — ступенчатая граница в пределах разрешения трассировки. Изолированные контуры могут упрощаться с существующей проверкой пересечений, ориентации и вложенности. Невалидная геометрия и превышение бюджета вызывают конкретную ошибку, а не исчезновение объекта.

«Убрать светлую кайму» — локальное добавление к маске возле уже исключённого фона. В GUI полоса равна двум пикселям исходника, ограничивается светлотой OKLab L≥0,72 и расстоянием до белого. Чёрный контур и защита не стираются. Это не полноценное восстановление foreground/alpha после смешивания с белым: тёмные серые JPEG/AA-пиксели могут требовать ручной корректировки палитры или маски. Через разрыв в контуре цветовая связность не распознаёт замысел; для этого есть защита и восстановление.

## Классификация и порядок

`AutoProfile` задаёт экспериментальные физические пороги: Running до 0,65 мм, Satin 0,8–8 мм, минимальная деталь 0,15 мм², осевая сетка до 0,15 мм. Пороги — стартовый профиль для проверки, не свойства конкретной ткани.

Удлинённый прямоугольник получает настоящие пары rails по исходным границам. Замкнутая окантовка из двух колец может использовать сами outer/inner rails с детерминированным seam и проверкой всех сечений. Прочие узкие области проходят существующие skeleton/axis-инструменты и `semi_auto_satin`. Проверяются реальная ширина, containment, складки/пересечения и сохранение не менее 97% площади исходной области; неподходящие концы, развилки, неоднозначные соответствия и слишком широкий Satin сохраняются как Tatami с причиной. Для автоматической глади длина разрешённого стежка вычисляется по полным диагоналям обоих вариантов начала, включая компенсацию, замкнутый seam и квантованные координаты, с запасом 0,15 мм. Ограничение длины Татами 3,5 мм не переносится на гладь: если цельная диагональ не помещается в машинный предел, сохраняется Татами с причиной, вместо скрытого добавления прокола посередине глади. Тонкие линии получают редактируемый Running-граф. Простое присвоение enum Satin без rails не считается успешной классификацией.

Работа ограничена числом объектов, размером осевой сетки и бюджетом геометрии. Отмена не применяет частичную классификацию. Глобальная сортировка по RGB при растровом импорте удалена; ручной порядок объектов имеет приоритет. Оптимизация разрешена только внутри последовательного блока одного цвета. Если любые исходные bounds блока соприкасаются или перекрываются, весь блок сохраняет порядок; это консервативная проверка зависимостей вместо глобального графа перестановок. Для раздельного блока применяется ближайший вход, а результат откатывается, если фактическая генерация увеличила число или длину Jump. Автоматическое удаление нижней заливки под деталями не выполняется.

Маршрутизация Tatami соединяет однозначные пары интервалов соседних строк в блоки; split/merge создаёт новые блоки. Ограниченная оценка вариантов начала сохраняет все исходные fill-сегменты, исходную конечную точку и детерминированный scanline-fallback, если кандидат не улучшает допустимую стоимость. Швейный переход выполняется только по целиком проверенному прямому отрезку внутри геометрии прохода и с ограничением длины; иначе применяется Jump с отдельной политикой обрезки. Многошаговый граф скрытых переходов, оценка видимости под будущим верхним слоем и глобальный лимит повторного прохождения travel не реализованы. Плотность сегментов и отдельная роль Travel помогают увидеть избыточную нить, но не заменяют эти оптимизации.

## ELAB и фоновые задания

ELAB v5 сохраняет исходное изображение, физический масштаб, `RasterRecipe` с параметрами/палитрой/масками, исходные идентичности регионов, структурированные диагностические сообщения и машинный профиль. Читаются старые v1–v4; новые поля получают значения по умолчанию. Старые редакторы не должны молча открывать v5 с потерей масок. Лимит встроенного исходника — 12 MB, проекта — 32 MB. Подходящие оригинальные PNG/JPEG сохраняются точными закодированными байтами, без предварительного полного PNG-перекодирования: небольшой JPEG не отклоняется из-за размера его PNG-эквивалента. Файловый API декодирует и встраивает один снимок байтов; GUI-worker проверяет соответствие исходника замороженным пикселям предпросмотра и передаёт сохранённый `SourceImage` в общий tracer. При изменении физической ширины обновляются только метаданные масштаба. PDF/пиксельный API без закодированного исходника использует lossless PNG. Новый импорт не уменьшает исходник скрыто ради лимита: если полное представление не помещается, требуется явный меньший исходник.

Генерация из изменённых объектов не запускает трассировку PNG. «Повторно оцифровать исходник» — отдельная операция. Ручной override переносится только при доказанном совпадении исходной геометрии и цвета. Изменение топологии у вручную исправленного региона вызывает конфликт; удалённые импортированные объекты не должны восстанавливаться, вручную добавленные сохраняются. Автоматическая классификация обновляет fingerprint базового состояния, сохраняя исходную region identity.

Трассировка, классификация и генерация выполняются вне UI-потока. Задание имеет идентификатор ревизии, fingerprint документа/импортных настроек и cancel token. Устаревший результат отбрасывается. Полный результат применяется одной транзакцией Undo; ошибка/отмена сохраняет документ и последний валидный план. После правок план помечается устаревшим, экспорт требует актуальной генерации.

## Проверки и источники

Диагностика разделяет верх и подложку, проверяет отсутствие верха/пересечения запрещённых областей, длины, puncture density и приближённое покрытие сегментами. Покрытие и плотность проколов — разные показатели. Ограниченный геометрический sampling и независимый reader не заменяют пробную отшивку. Точные выполненные проверки, непокрытые случаи и размеры диагностических допусков перечислены в validation-файле.

Зависимости в текущем `Cargo.lock`: `image` 0.25.10, `geo` 0.31.0, `cavalier_contours` 0.9.0, `eframe` 0.33.3, `pdfium-render` 0.9.5 / PDFium 8125. Новых производственных библиотек для трассировки не добавлено; лицензии существующих зависимостей продолжают включаться существующим packaging workflow.

Предметные первоисточники, проверенные 6 ноября 2026:

- [OKLab, Björn Ottosson](https://bottosson.github.io/posts/oklab/): матрицы редакции 2021-01-25; автор предоставляет формулы/пример в public domain и по MIT. В Rust использованы математические преобразования с явной sRGB-линеаризацией.
- [GIMP 3, Fuzzy Select](https://docs.gimp.org/3.0/en/gimp-tool-fuzzy-select.html): исходный цвет, интерактивный допуск, различие 4/8-связности. В EmbroideryLab своя радиальная механика жеста по требованию задачи.
- [OpenCV 4.13.0, floodFill](https://docs.opencv.org/4.13.0/d7/d1b/group__imgproc__misc.html): fixed-range относительно seed; OpenCV не является зависимостью.
- [geo 0.31.0](https://docs.rs/geo/0.31.0/geo/): boolean operations, buffer и validation; само название topology-preserving не заменяет проверки.
- [Ink/Stitch: Tatami](https://inkstitch.org/docs/stitches/fill-stitch/), [Satin](https://inkstitch.org/docs/stitches/satin-column/), [routing](https://inkstitch.org/tutorials/routing/), [компенсация](https://inkstitch.org/tutorials/push-pull-compensation/): предметная модель проходов и rails, не источник портированного кода.
- [PyEmbroidery](https://github.com/EmbroidePy/pyembroidery), [MIT license](https://github.com/EmbroidePy/pyembroidery/blob/main/LICENSE): независимая проверка записанного DST; используемая harness-версия фиксируется в validation.

Ядро проекта остаётся MIT. Код Ink/Stitch/Potrace под GPL не копировался и не портировался построчно. VTracer/Potrace не подключены: в этой реализации выбран общий label grid существующего tracer-а. Фактическая проверка на ткани не проводилась.
